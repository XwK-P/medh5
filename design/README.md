# Design records

Historical documents from the design of format version 1.0, kept for the
reasoning rather than as documentation.

- **[Design proposal](medh5-1.0-proposal.md)** — what broke in medh5 0.6.0, with
  measurements; the principles, the alternatives weighed and rejected, the costs
  accepted, the decisions taken.
- **[Implementation plan](medh5-1.0-implementation-plan.md)** — package layout,
  public API, phased delivery, test strategy.

Both were written in August 2026, *before* the code they describe existed, and
neither has been revised since. **They are not documentation and are not
maintained.** Where one disagrees with the shipped format, the
[specification](../docs/spec/medh5-1.0.md) is right and these are simply old;
where one disagrees with the shipped package, the
[documentation](https://medh5.readthedocs.io/) is.

They are deliberately not published to the documentation site. A reader looking
for how to use the package should not land on a superseded internal plan, and a
release checklist rendered as unticked boxes on a public page says something
untrue about a format that has shipped.
